# 记忆系统设计

> 日期：2026-10-15。状态：方案已确认，已交付实现；实际范围与限制见 [记忆使用与验收](memory.md)。
> 已确认：长期记忆采用自然语言正文＋必要管理元数据，PostgreSQL 正文使用 TEXT。
> 本文记录目标设计；当前能力以 [功能模块清单](modules.md) 为准。

## 1. 目标与范围

让单 Agent 在跨任务、跨会话时复用用户偏好、项目决策和经过验证的经验，并支持查看、纠正和遗忘。

- 短期记忆：当前会话的消息、工具结果、执行状态与摘要，属于 Agent 运行基础设施。
- 长期记忆：值得跨会话复用的独立笔记，通过显式保存或自动提取写入同一套系统。
- RAG：独立管理外部文档与原文证据，不把摄取文档自动转成用户记忆。
- 高频任务状态由运行时或业务表维护，不反复写成长久笔记；会话摘要也不直接等于长期记忆。

## 2. 组成与边界

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| 会话状态 | 稳定会话 ID、历史恢复、裁剪与摘要 | agent/ 组合官方能力；不自建消息协议，不用 RunRepository 代替 Checkpointer |
| 长期记忆管理 | 增删改查、来源、范围、去重、冲突与过期规则 | memory/ 依赖 Repository 协议，不直接访问 PostgreSQL、文件或网络 |
| 记忆提取 | 从新增对话和已验证结果生成新增、补充或替代建议 | 只产生候选，不拥有直接落库或扩大权限的能力 |
| 上下文组装 | 相关性检索、预算、数据标记、实际来源记录 | context/ 是 Memory/RAG 进入 Prompt 的唯一组装入口 |
| 持久化与索引 | PostgreSQL、事务、版本校验、索引更新和 migration | storage/ 实现协议；索引可重建，正文是唯一内容事实源 |

application/ 提供管理用例、协调运行与提取，并传递可信的用户、工作区和项目标识；
CLI、MCP 和后续界面只调用这些用例。domain/ 不依赖框架或基础设施。

数据库、索引、文件和模型出站操作统一经 tools/、ToolExecutor 和 safety/；
Context 通过受控访问协议调用记忆查询，不能拿到裸数据库或未授权 Store。
工具返回的记忆同样由 Context 的统一格式组装，避免第二套 Prompt 入口。

## 3. 数据模型与存储

| 模型 | 必要字段 |
| --- | --- |
| Session | id、user_id、workspace_id、project_id（可选）、created_at；id 映射框架 thread_id |
| MemoryRecord | id、content、kind、scope、sources、version、created_at、updated_at、expires_at（可选） |
| Scope | user_id、范围类型及对应 workspace_id/project_id；只允许当前授权范围 |
| MemorySource | origin（显式/提取）、session_id/message_ids/run_id（按来源填写） |
| MemoryCandidate | 候选正文、来源、操作、目标 ID 和预期版本（更新时）；初期仅存在于处理流程 |
| 查询及上下文结果 | 查询文本、允许范围、数量与过滤条件；命中相关性；实际注入的 memory_ids/chunk_ids |

kind 用于区分偏好、决策和经验，不采用不同卡片格式。正文是一条可独立理解和更新的知识，
保留主体、关系、时间和适用条件；来源只保存必要引用，不复制整段敏感对话。
例如：“workstation-agent 项目统一使用 uv 管理 Python 依赖。”

Session 对应多个 Run 和框架消息；候选根据来源指向消息或 Run，提交后成为长期记忆。
一条记忆可以关联多个来源，一个会话也可以产生多条记忆；长期记忆不归属于 RAG 文档。
来源引用失效时不臆造证据，也不把原始会话删除默认解释为长期记忆删除。

PostgreSQL 将 content 保存为 TEXT，常用过滤字段设列，来源可采用关联表或 JSON 元数据。
不维护独立、可分别编辑的事实卡片和检索描述。更新通过预期 version 校验及事务提交；
正文与持久化索引保持一致，派生缓存失效后重建，读取时核验记录仍有效。

## 4. 使用流程

### 4.1 显式保存与维护

用户明确要求或管理入口 → Application 确定操作和范围 → 工具权限校验
→ 校验正文及来源 → 查找同范围相关记录 → 新增/合并来源/局部更新 → 事务提交 → 返回操作结果。

支持按 ID 查看、按条件列表、任务相关检索、按 ID 修改与删除。
明确指定 ID 的管理操作不额外依赖模型；自然语言指令可先由 Agent 解析。
不能把相似度直接当作重复或冲突结论；更新不得遗漏原有适用条件。
未发现旧记录不代表用户意图新增，更新目标缺失或版本冲突应明确返回，不静默覆盖。

### 4.2 任务开始时召回

恢复会话 → Application 提供可信范围 → Context 经授权入口查询长期记忆及所需 RAG
→ 过滤失效和不相关结果 → 按相关性、条数与独立预算组装 → 官方 Agent 执行。

缺少项目标识时不查询其他项目；没有相关记忆就不注入。
记忆按完整条目裁剪，记录实际来源；动态检索上下文不逐轮永久追加到会话历史。
记忆不能覆盖当前明确要求、系统规则或工具权限，外部文档事实仍以原文证据为准。

### 4.3 自动提取

任务结束后读取本次新增用户信息与已验证结果 → 提取候选 → 查询相关旧记忆
→ 判断新增、重复、补充、替代或不确定 → 校验来源、范围、版本和权限 → 提交。

建议默认关闭，通过配置开启；按新增消息范围去重，限制输入、调用次数与费用。
首次可采用有界的运行后处理，不引入常驻后台服务；处理结果单独返回，明确可能增加响应耗时。
用户纠正可替代旧值；未经验证的推断不能覆盖明确陈述，不确定候选暂不生效。
任务 completed 不等于所有工具操作成功，不从模型自述、检索记忆或整段 RAG 输出循环提取事实。

## 5. 关键边界与失败处理

| 情况 | 处理建议 |
| --- | --- |
| 跨用户、跨项目访问 | 查询前按可信范围隔离；按 ID 修改和删除也必须校验所有权，不能只凭 ID 操作 |
| 冲突和并发 | 模型只提建议；程序检查目标、范围与版本。来源同样可靠时才比较适用时间，不能机械采用最新文本 |
| 过期与失效 | expires_at 到期即排除；事实纠正更新原记录及来源，正文旧值不进入默认审计 |
| 遗忘 | 删除正文、索引、缓存及相关派生摘要；失效待处理候选，禁止旧消息范围再次提取 |
| 原始会话与遗忘 | 明确区分删除记忆与清除会话；遗忘后若旧会话仍含事实，应提示范围，并提供清除或重置能力 |
| 秘密与注入 | 密钥、令牌等不进入正文、日志和索引；文档或工具中的指令不能授权记忆写入 |
| 权限 | 建议读取 SAFE_READ，新增/修改 CONTROLLED_WRITE，删除 DESTRUCTIVE，额外模型出站 SENSITIVE；授权策略独立校验 |
| 失败 | 拒绝授权时无副作用；索引异常时返回明确错误或授权范围内可靠降级；提取失败单独报告，不修改已完成 Run 状态 |

“删除”默认保证应用层不再召回，不承诺数据库页、备份或先前已发送到模型的内容已被物理抹除。
防止旧内容重建至少需要删除版本/处理水位和提交前校验；仅凭文本方案无法保证未来改写后的同义内容永不出现。
日志仅保留操作类型、状态和必要 ID，不默认输出正文、原始工具内容或完整 Prompt。

## 6. 框架复用与必要扩展

| 能力 | 选择与理由 |
| --- | --- |
| 会话和摘要 | 复用 [AgentState、Checkpointer 与官方摘要能力](https://docs.langchain.com/oss/python/langchain/short-term-memory)，本机采用官方 PostgreSQL Checkpointer |
| 记忆提取 | 后续优先评估 [LangMem 的无存储依赖核心 API](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)，输出候选后走本项目受控提交 |
| 存储和检索 | 优先复用 [Store 官方接口](https://docs.langchain.com/oss/python/langchain/long-term-memory)及成熟检索组件，通过适配器满足现有 Repository 协议 |
| 项目扩展 | 作用域授权、来源验证、冲突提交、遗忘和预算属于项目业务规则，保留最小自定义实现 |

持久化统一使用 PostgreSQL。官方 PostgresSaver 负责会话检查点；业务记忆通过现有 Repository
协议保存，以满足整批版本校验、遗忘保护和容量约束。数据库驱动及连接池采用 Psycopg，
不自行实现官方检查点或通用 Store。部署和维护边界见 [数据库说明](database.md)。
自动提取复用 LangMem，成本仍是依赖维护和额外模型请求；中文检索继续复用既有策略。

## 7. 实施顺序与验收

1. 长期记忆闭环：调整模型与 Protocol、先补作用域/无关召回回归测试，再交付 PostgreSQL、授权 CRUD、
   管理入口和 Context 接入；覆盖重启可用、越权拒绝、更新冲突、过期及删除。
2. 会话能力：稳定会话 ID、官方 Checkpointer、摘要与清除入口；验证续聊、隔离、
   敏感数据保留策略和动态上下文不重复持久化。与 Memory 分开交付。
3. 自动提取：验证框架组件效果，加入有界后处理、幂等与遗忘保护；验收误写、冲突、
   失败不影响主任务及成本，达到要求后再决定默认策略。

不保留旧对象的兼容导出或重复运行链；同步修改调用方、测试和文档。
新表通过版本化 migration 引入。当前仅有内存记忆，无默认持久化数据可迁移；
实际发现已有自定义数据时需在实施前明确迁移/导入方案，派生索引从已保留正文重建。
框架 Checkpoint 表由官方适配器维护，应用元数据和框架版本升级分别管理。

实现时为新配置提供默认值、环境变量和 doctor 检查，至少覆盖开关、存储位置、
记忆预算与提取限制；路径规范化并限制在配置工作区内。
按仓库要求执行 unittest discover、doctor，涉及 migration、打包资源或入口点时额外 uv build。
增加确定性的提取夹具和 CRUD/权限集成验收，真实模型质量另行评估，不把协议测试当效果证明。
