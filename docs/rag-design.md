# RAG 设计方案与待定事项

> 日期：2026-10-10。总体方案已确认，第一阶段实现已交付；实际配置和边界见 [RAG 使用与验收](rag.md)。
> 当前实现状态以 [功能模块清单](modules.md) 为准。

## 1. 目标与范围

RAG 管理外部文档，为现有单 Agent 提供可追溯的原文证据。Memory 继续管理用户和任务经验，两者分别存储、检索。

本方案采用：结构分块、块级上下文前缀、BM25 与向量混合检索、RRF 排名融合、重排和按需上下文扩展。
第一阶段支持工作区内的 Markdown 与纯文本，先建立确定的检索管线，再向现有 Agent 暴露检索能力。

PDF、Word、网页摄取及 OCR 留待后续扩展；初期不引入独立 RAG Agent、多 Agent 或知识图谱。
多跳问题需要多次检索与证据整合，不能仅通过增加分块重叠或上下文前缀解决。

## 2. 当前实现基础

| 组件 | 已实现能力 | 后续范围 |
| --- | --- | --- |
| LangChain Document | 原文 page_content、稳定 id、metadata 中的来源位置和派生上下文 | 更多来源格式 |
| SourceDocument / IndexSnapshot | 来源身份、原生框架文档及按块 ID 关联的向量 | 更大规模的快照与索引 |

| HybridSearch | 官方检索组合，直接输入输出 Document；BM25Plus、向量、RRF 和重排 | 真实语料和模型效果验收 |
| ContextBuilder | 官方 Runnable 接口、原文证据、完整预算和实际来源记录 | 精确 tokenizer 预算 |
| CLI / MCP / Agent | 摄取、删除、查询与健康检查，共享授权用例 | 更多格式和交互入口 |

原有 TextChunk、查询及命中包装、关键词仓库接口和兼容导出已移除；旧索引从原文重建。
具体边界及升级方式见 [RAG 使用与验收](rag.md)。

## 3. 模块边界

| 模块 | 职责与约束 |
| --- | --- |
| application/ | 提供摄取、更新、删除和检索用例，协调组件和任务结果 |
| rag/ | 组合官方分块、检索组件并实现来源与预算扩展；索引边界通过 Protocol 解耦 |
| models/providers/ | 适配上下文生成、embedding 和重排的模型能力，供应商 SDK 限制在此处 |
| storage/ | 实现文档、块、索引元数据等持久化；通过版本化 migration 引入结构 |
| tools/ 与 safety/ | 工作区文件读取、索引写入、外部模型调用等副作用通过授权执行边界 |
| context/ | 唯一模型上下文组装入口，统一处理原文证据、引用、预算及检索数据标记 |
| agent/ | 使用现有官方 Agent / LangGraph 编排任务，不直接读取文件、数据库或访问网络 |
| interfaces/ | CLI、MCP 等接口只调用 Application 用例 |

纯文本分块和排序可直接处理内存数据；带副作用的适配器必须通过项目的工具执行与权限策略。
新增工具声明 PermissionLevel 和参数 schema；文件路径规范化并限制在配置的工作区内。
检索工具输出也通过 Context 的统一证据格式进入模型，避免出现第二套上下文组装逻辑。

## 4. 文档摄取与分块

### 4.1 处理流程

```text
工作区文档
  → 权限校验与读取
  → 解析、规范化及来源位置映射
  → 结构分段与递归分块
  → 块级上下文增强
  → 原文及元数据保存
  → BM25 / 向量索引构建
  → 完整索引版本发布
```

### 4.2 分块规则

- Markdown 按标题层级划分章节，保留完整标题路径；代码围栏中的标题字符不得被识别为章节。
- 纯文本优先以空行、段落为边界。
- 过长章节依次按段落、换行、中英文句末标点和字符拆分。
- 重叠只发生在同一章节内，尽量沿完整语句或段落保留，实际重叠长度可以小于目标值。
- 小章节无需为凑满长度跨章节合并；命中后的扩展由检索阶段处理。
- 代码块和表格尽量完整保留；超长时按行拆分，并保留语言、表头等解释信息。
- 同一输入及分块配置应产生可复现的边界，不丢失有效原文内容。

初始实验参数为块上限 1000 字符、重叠目标 100 字符，均可配置。
字符数不等于 token 数；接入 embedding 模型后，必须校验“前缀 + 原文”的总输入限制。
超长单行、表头和代码围栏的预算处理需要在实现前确定。

当前使用 markdown-it-py 的结构 token 与行映射解析 Markdown，递归分块使用官方 RecursiveCharacterTextSplitter。
MarkdownHeaderTextSplitter 会处理空白和正文格式，无法直接保证原文定位，因此使用成熟解析器补齐结构位置。
rag/ 只适配来源区间、章节关联和格式保护，分块算法由框架提供。

### 4.3 来源与关联

当前使用框架 Document.id / page_content / metadata 承载以下字段；SourceDocument 单独记录来源身份：

| 字段 | 用途 |
| --- | --- |
| document_id / checksum | 标识来源文档及内容版本 |
| id / ordinal | 标识块及其文档内顺序 |
| page_content | 原文证据，不混入模型生成的说明 |
| heading_path / section_id | 标题层级及父章节，用于理解和扩展上下文 |
| previous_chunk_id / next_chunk_id | 同版本文档内的相邻块关联 |
| source_span | 原始文本字符区间和行号，支持准确引用 |
| context_prefix | 块专属上下文说明，与原文独立保存 |
| context_provenance | 记录说明来自结构规则还是模型，以及生成版本 |
| index_generation | 记录分块、前缀、embedding 和索引配置的版本 |

规范化后的偏移不能直接当作原文偏移。需要保留位置映射或采用能维持原文定位的解析方式。
重复表头、补充代码围栏等辅助文本单独标识，不能伪造它们在原文中的连续位置。

## 5. 上下文增强索引

### 5.1 前缀的作用

每块添加一段简短、专属的上下文说明，补充主体、所属章节、适用范围或时间背景。
它回答“这个块处于什么背景”，不能只复述块内容，也不应给所有块贴同一份全文摘要。

示例：

```text
原文：
默认仅允许只读操作，写入操作需要审批。

上下文前缀：
本片段来自 Workstation Agent 的工具权限章节，
描述 ToolExecutor 执行工具时的默认权限及审批要求。

索引文本：
上下文前缀 + 原文
```

### 5.2 生成与使用规则

- 优先从文档标题、章节路径等确定信息生成基础前缀。
- 信息不足时，可将原文块及必要章节背景交给统一模型能力，生成块专属说明。
- 说明只能使用来源中有依据的信息，不补写文档未陈述的结论。
- 模型生成说明是派生数据；保留生成来源和版本，不能作为独立事实证据。
- BM25 与向量索引均使用增强文本；答案事实及引用必须回到原始 content 和来源位置。
- 文档或生成配置变化时使旧缓存失效，并与索引版本同步更新。
- 生成失败应有明确状态；是否允许退回结构前缀、是否继续发布索引属于待定策略。

前缀长度需要与 embedding 总输入预算共同控制；模型调用发生在摄取阶段，可缓存结果。
使用章节背景还是全文背景、如何处理超长文档，以及生成成本上限均需评估。

## 6. 检索设计

### 6.1 单次检索管线

```text
查询 + 文档过滤条件
  → BM25 召回 与 向量召回
  → RRF 排名融合、按块 ID 去重
  → 问题与候选块重排
  → 选择证据块
  → 按需扩展父章节 / 相邻块
  → 合并重叠原文、按 token 预算裁剪
  → 返回原文证据、来源位置和检索状态
```

过滤条件必须同时作用于两路召回、重排输入和上下文扩展，不得在扩展时带入过滤范围之外的内容。

### 6.2 混合召回与融合

BM25 负责类名、配置项、错误码等精确术语；向量检索负责同义表达和自然语言语义匹配。
中文 BM25 需要专门确定分词策略，保留英文标识符，并保持建索引与查询的处理方式一致。

融合先使用 RRF，按照两路结果的排名计分，避免直接相加不同量纲的 BM25 分数和向量相似度。
需要定义融合常数、稳定的同分排序和去重规则；融合分数不是置信概率。

### 6.3 重排与上下文扩展

重排模型同时读取问题和“前缀 + 原文”候选，筛选与问题更相关的块。
命中块存在指代、前置条件或连续步骤时，再取父章节或相邻块，避免每次无条件返回整章。

扩展必须保持同一文档版本、过滤范围和预算；重叠区间合并，辅助信息与原文证据分开。
重排失败的降级策略、扩展触发条件及扩展后是否再次排序均待确定。

### 6.4 初始实验参数

| 参数 | 起始值 | 说明 |
| --- | --- | --- |
| BM25 召回数量 | 20 | 控制精确匹配候选池 |
| 向量召回数量 | 20 | 控制语义候选池 |
| 融合后重排数量 | 最多 30 | 去重后不足时使用实际数量 |
| 最终命中块数量 | 约 5–8 | 实际受证据覆盖和 token 预算限制 |
| 扩展范围 / token 预算 | 待定 | 包含父章节、相邻块、来源标签的实际开销 |

这些参数是实验起点，不是已经验证的最优值。无证据或证据不足时返回明确状态，不为凑数量补入无关块。

## 7. 多跳查询与现有 Agent

上下文增强索引改善块的可理解性，父章节扩展补充局部背景；跨文档依赖仍可能需要多次检索。
多跳检索既可由固定流程驱动，也可由 Agent 根据证据决定下一步，后者属于 Agentic RAG。

本项目先实现独立、确定的检索管线，后续以工具接入现有单 Agent：

1. 将复杂问题拆成可检索的证据需求。
2. 调用检索工具取得原文及引用。
3. 依据已确认的实体或关系构造下一步查询；存在依赖的步骤顺序执行。
4. 合并证据，检查各子问题是否都有支持。
5. 证据足够时回答；预算耗尽或检索无进展时说明缺少哪些证据。

继续使用官方 Agent / LangGraph，不新增独立 RAG Agent 或手写第二套 Agent 循环。
检索轮数、子问题数量、超时、token 预算和重复查询停止规则需明确配置。
对话历史改写属于后续会话能力，不能将当前无持久化会话的入口描述为已支持历史感知检索。

## 8. 存储、更新及运行约束

- 以内容版本和处理配置识别重复摄取；稳定块 ID 与缓存键的计算方式待定。
- 文档、块、前缀、BM25 和向量索引必须引用一致的版本。
- 更新先构建新版本，完整成功后发布；失败不得暴露原文与索引混用的半成品。
- 删除或更新时处理旧块、派生前缀和两路索引，避免返回过期证据。
- 检索读取同一索引版本；并发发布和失败恢复方案随存储实现确定。
- 错误和日志不泄露 API Key、令牌或敏感原文；日志以阶段、耗时、数量和状态为主。
- 检索内容统一标记为数据，不允许来源文档中的指令触发权限绕过。
- 对外模型是否接收全文、章节或块内容，要符合工作区数据的出站授权策略。
- 新配置提供默认值、环境变量说明和 doctor 检查；实际名称在配置设计时确定。

## 11. 测试与验收

单元测试放在 tests/unit/：分块边界、原文位置、过滤、融合排序、去重、扩展和预算。
边界测试放在 tests/integration/：文件读取、模型适配、持久化、索引更新删除、超时及失败恢复。
完整摄取到回答、多跳检索和权限拒绝任务后续放在 tests/scenarios/。

评估集至少包含：精确术语、语义改写、中文查询、指代、跨章节、跨文档、两跳依赖、无答案和版本更新。
对比原文基线、上下文增强、混合召回、重排和扩展的增益，同时记录成本与延迟。

重点指标为 Recall@K、MRR 或 nDCG、多跳必要证据完整召回率、答案引用支持率和端到端正确率。
报告样例数量、模型及索引配置和延迟；指标门槛待定，不引用其他项目的提升比例作为本项目承诺。

所有改动至少执行：

```powershell
uv run python -m unittest discover -s tests -v
uv run workstation-agent doctor
```

涉及 migration、打包资源或入口点时额外执行 uv build。
完成时应有正常与关键失败路径测试、清晰任务状态、可追溯引用、配置与 doctor 文档，
并根据真实可用能力更新 modules.md；设计完成不等于 RAG 功能完成。

## 13. 第一阶段实施决策与剩余事项

- 解析采用 markdown-it-py，分块采用官方 RecursiveCharacterTextSplitter，保留原文位置、代码与表格保护。
- 检索采用 rank-bm25 的 BM25Plus、官方 InMemoryVectorStore、EnsembleRetriever 和 ContextualCompressionRetriever；
  项目通过官方扩展接口补充术语处理、来源映射、预算和授权，不手写通用算法。
- 新增文本分块、经典检索、Markdown 解析及 BM25 依赖，uv.lock 固定版本；安装与运行成本见 rag.md。
- 破坏性调整内部对象、Context 和仓库接口，不保留旧入口或转换链；旧索引只标记来源并要求从原文重建。
- 原文位置采用 Python 字符半开区间及一基行号；派生前缀和辅助格式独立保存。
- SQLite 原子发布 SourceDocument、原生 Document 及按块 ID 关联的向量，移除重复词频；migration 003 标记格式 3。
- 中文初始采用单字 / 双字滑窗，向量采用精确余弦扫描，适用于当前小型知识库。
- 模型复用官方 LangChain OpenAI 兼容集成，由配置提供名称，不绑定实际供应商。
- 默认结构前缀 + BM25，配置模型并授权出站后启用生成前缀、混合召回和重排。
- RRF 常数 60；模型或索引失败明确返回错误，不静默切换处理模式。
- 命中块优先分配预算，再扩展邻接或所属章节，合并原文并记录实际块 ID。
- CLI 摄取、更新和删除，CLI/MCP/Agent 共享查询与健康检查，多跳复用单 Agent。
- 固定样例、模型 HTTP 边界、Agent 两跳检索和资源停止已纳入测试；外部模型质量仍待验证。

第 9 节保留设计时的选型问题，第 10 节记录实施进度；实际配置和剩余边界见 rag.md。
剩余事项为实际模型选型、生产语料评估、延迟和费用校准、分词器优化及更大规模索引。
