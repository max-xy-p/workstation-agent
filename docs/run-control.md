# 工具审批、超时与取消

运行控制负责让任务在需要用户决定、超过时间限制或被取消时明确停止。
模型与工具循环仍由 LangChain 的官方 Agent 执行；审批恢复使用 LangGraph 的检查点、`interrupt` 和 `Command`。

## 查看和恢复审批

运行前按 [Agent 使用说明](agent.md) 配置模型。默认 MCP 模式还需要启动本机工具服务，
下面使用 `local` 演示同进程工具；替换为 `mcp` 即可使用同一审批流程。
需要跨 CLI 命令恢复时，首次运行就必须保存会话：

```powershell
uv run workstation-agent run "把 README.md 加入知识库" --transport local --session review
uv run workstation-agent approvals review --transport local
```

第一次命令遇到未授权工具后返回 `waiting_approval` 和 `approvals`，不会执行被拒绝的操作。
第二次命令列出中断 ID、工具名称、参数和参数指纹。检查实际操作后，逐项批准或拒绝：

```powershell
# 把 approval-id 替换为 approvals 返回的中断 ID；有多项时重复 --decision。
uv run workstation-agent resume review --transport local --decision "approval-id=approve"
# 拒绝同样使用 resume，把 approve 改为 reject。
```

决定必须覆盖当前全部待审批项，重复、遗漏或旧中断 ID 会被拒绝。
批准仅针对该工具的完整原始参数；后续调用仍检查权限。拒绝结果作为工具错误交回模型，
模型可解释原因，但拒绝本身不算执行成功。等待审批的会话不能另开一轮任务覆盖待执行操作。
停止运行时会补上缺失的工具结果，注明实际结果尚需核对，再清除待执行节点，避免续聊时留下不完整的工具调用。
官方 run_limit 只覆盖一次图调用，不能单独限制多次审批恢复。
`agent/run_boundary.py` 在新任务开始时重置官方持久计数，恢复时不重置，配合 thread_limit 继续使用原任务预算；摘要尝试次数也随检查点保留。
恢复沿用原 Run ID 和框架调用计数，不重新提交用户任务，也不重放已成功的并行工具节点。
每次恢复返回本次继续执行的步骤，领域 RunRepository 不承担完整执行历史恢复。

未启用会话持久化时，框架只使用内存检查点。同一个 `AgentApplication` 对象可以恢复，
CLI 退出后这些检查点消失；需要重新运行并指定 `--session`。持久化会话按现有用户、工作区和项目身份隔离。
检查点中的 `run_control` 使用格式版本 1，保存运行身份、绝对截止时间和是否结束；缺少该记录的旧审批不能恢复。

## 时间限制与取消

`WORKSTATION_AGENT_RUN_TIMEOUT` 是整次运行的时间限制，默认 300 秒；模型、工具、摘要、
记忆提取以及审批等待共用该截止时间。恢复审批不会重新计时，已过期审批不能执行。
`WORKSTATION_AGENT_MODEL_TIMEOUT` 仍限制单次模型请求和 MCP 读取，默认 30 秒。
`doctor` 同时显示这两个配置，非正数或非有限数值会在加载配置时被拒绝。

应用调用方给 `run_task` 传入 `on_started` 回调即可在开始时取得 Run ID，
再用 `AgentApplication.cancel(run_id)` 取消正在执行的任务。状态栏的 task_id 可以跨多轮沿用，不能代替 Run ID。
CLI 用户可以按 Ctrl+C。取消后 Run 标为 `cancelled`，并继续向调用方传播取消异常；
超时返回 `limit_reached`。已经停止的运行不能通过旧审批重新启动。
新工具调用在执行前检查停止信号；文件读取和目录遍历也在循环中检查。
线程工具在退出前继续占用会话锁，避免旧线程仍在写入时另一轮任务进入同一会话。

取消采用协作方式：Python 不能安全强杀任意工作线程，已经完成的外部副作用也不能自动撤销。
不检查停止信号的第三方阻塞调用可能延迟收尾，仍需依靠其请求超时。
进程突然退出与“外部操作成功但检查点尚未保存”之间也不存在通用事务；
发生这类崩溃时应先核对外部结果，不能把普通审批恢复理解为任意工具的严格一次执行保证。

## 模块分工和权限边界

- `application/service.py` 是运行用例入口，提供查看审批、恢复、取消与任务项验收；不直接读写数据库或访问网络。
- `tools/langchain.py` 把执行器返回的权限要求转换为官方中断，恢复后校验工具参数指纹。
- `tools/execution.py` 传递一次调用授权和停止信号。执行器仍先校验参数，再检查权限；授权在调用结束时清除。
- MCP 客户端通过官方请求元数据传递授权范围与截止时间；服务端校验授权与工具、参数相符后才进入执行器。
  元数据不属于模型可填写的工具 schema。服务令牌代表可信调用方，持有令牌的调用方具有提交审批的能力。
- `storage/checkpoints.py` 声明带官方类型的存储 Protocol；权限包装器直接调用后端方法，SQLite 实现再调用官方 SqliteSaver。
  序列化和检查点元数据沿用框架要求的宽泛类型，业务方法不使用字符串转发。

官方 HumanInTheLoopMiddleware 适合按工具名预先配置审批；本项目的最终权限还取决于参数、
运行配置和服务端执行器结果，因此在官方工具扩展点做小型适配，不另建审批状态机。
收尾通过官方 `aupdate_state` 指定 `tools` 节点并以 `END` 清除待执行节点；
节点名称随官方工厂版本验收，不读取框架私有状态。
维护成本集中在工具中断、MCP 元数据和检查点恢复协议；升级框架时必须重跑本地、SQLite 重启和真实 MCP 审批测试。
检查点继续清除工具正文、artifact 和已知秘密，工具校验子图显式禁止继承外层检查点。
如果原始参数包含被脱敏的秘密，恢复后的参数指纹不再相符，程序会拒绝执行；这类秘密应通过配置传入，不能依赖会话恢复原文。
