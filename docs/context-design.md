# Agent 上下文管理方案

> 日期：2026-10-17。状态：已确认并实现，使用方法见 [上下文管理](context.md)。
> 审核后增加结构化任务状态栏；实现范围、配置和限制见使用说明。当前能力以 [模块清单](modules.md) 为准。

## 1. 目标与范围

每次调用模型前，统一决定带入哪些信息、占用多少 Token，以及超限时如何压缩。
无论是否启用会话持久化，都执行相同的预算与消息检查。

本方案覆盖完整请求计量、内容选择、分级压缩、记忆刷新和必要的来源记录。
继续使用官方 Agent 循环、现有记忆与 RAG 检索策略，不增加多 Agent 或工作流引擎。
状态栏包含进度记录，不引入任务规划引擎；审批恢复和新的长期记忆分类不在本次范围。

## 2. 当前问题

- Token 仅局部统计：历史、记忆、RAG 和工具输出分别限制，完整请求没有统一预算。
- 裁剪与持久化耦合：默认未启用会话时，任务内部的消息仍可能不断增长。
- 组装过程分散：ContextBuilder 生成消息后又被转换成字符串，中间件再拼接。
- 工具输出冗余：RAG 的原文同时出现在结构化结果和格式化正文中，旧结果随历史重复发送。
- 内容刷新不足：启动时召回的记忆不随任务进展更新，续聊恢复后也缺少精确的结果引用。

## 3. 模块分工与数据

| 模块 | 调整后的职责 | 必须保持的边界 |
| --- | --- | --- |
| `application/` | 提供可信身份、当前任务与受控检索入口，协调刷新和结果记录 | 继续通过工具授权执行检索和其他副作用 |
| `context/` | 管理候选信息、预算、去重、保留规则和最终消息组装 | 不直接访问数据库、文件、网络或厂商 SDK |
| `agent/` | 通过官方模型调用中间件执行每次请求的上下文流程 | 保留官方运行循环，不在中间件中绕过工具权限 |
| `tools/` | 返回精简的模型可读内容及结构化引用，支持必要的按范围读取 | 权限和参数检查仍由 ToolExecutor 执行 |
| `models/` | 提供模型限制、计数适配及已授权的摘要能力 | 厂商 SDK 仍只出现在 providers 中 |
| `storage/` | 按现有保留约定保存、恢复会话 | 不决定哪些内容进入模型请求 |

在 `context/` 内按数据、预算、选择与组装划分文件；`agent/context.py` 保留为框架适配入口。
替换现有重复组装链，不保留两套上下文入口。所有新增接口有完整类型注解，并纳入 Pyright。

请求管理使用以下三类核心数据，不另建一套消息协议；任务状态栏和运行缓存另见 [使用说明](context.md)：

| 数据 | 必要内容 |
| --- | --- |
| 上下文条目 | ID、类别、内容、来源与版本、是否必须保留、是否仅本次请求使用 |
| 预算配置 | 模型窗口、输入上限、输出预留、安全余量、压缩触发阈值 |
| 选择结果 | 实际选入的条目、组装后的官方消息、计数方式、用量及舍弃原因 |

框架消息仍使用官方消息类型。条目用于保留来源和选择信息，最终才转换成模型输入。

## 4. 每次模型调用的流程

```text
读取当前任务和消息状态
→ 获取或刷新允许范围内的记忆候选
→ 整理历史与工具结果，去除重复内容
→ 计算完整输入预算
→ 超过触发阈值时执行分级压缩
→ 组装最终消息和工具定义
→ 再次检查预算与工具调用配对
→ 调用模型，并记录本次选择结果
```

最终计量必须位于动态内容组装之后，且后续适配不能再加入未计量的应用内容。
系统规则与检索数据分别表达；检索数据保留来源及“仅为数据”的标记，不提升为系统授权。
这不能单独保证消除提示注入，工具权限始终独立执行。

## 5. 预算与建议默认值

```text
可用输入 = min(模型输入上限, 模型上下文窗口 - 输出预留) - 安全余量
```

计量包含系统规则、用户与助手消息、工具调用参数、工具结果、记忆、RAG 内容、
工具参数定义及实际使用的结构化输出约束。输出预留同时用于限制实际模型输出。

| 配置含义 | 建议默认值 |
| --- | --- |
| 模型上下文窗口与输入上限 | 优先使用显式配置或可信模型资料；未知时要求配置，不猜测自定义模型容量 |
| 最大输出预留 | 2,048 Token，且不得超过模型输出限制 |
| 安全余量 | 1,024 Token |
| 压缩触发阈值 | 可用输入的 80%；最终发送仍须满足可用输入上限 |
| 额外摘要请求 | 默认关闭；启用后每次任务最多 1 次，仍须有模型出站授权 |

优先复用模型对应的计数能力；不支持准确计数时，使用官方计数工具保守估算，并标明估算方式。
估算与安全余量不代表绝对精确，需使用真实服务报告的用量校验偏差。
如果模型窗口太小、配置相互冲突或缺少必要限制，运行前给出明确配置错误。
实现时同步提供环境变量说明和 doctor 检查；普通无模型配置的诊断不发起网络请求。

## 6. 分级压缩规则

| 顺序 | 处理方式 | 保留要求 |
| --- | --- | --- |
| 1. 去重 | 同一范围、ID、版本的记忆或片段只选一次；RAG 正文只发送一份 | 不把内容相似当作同一事实，不合并不同来源的引用 |
| 2. 清理旧工具正文 | 优先清理较旧结果，保留必要状态、来源引用和最近仍在使用的结果 | 保留工具调用与结果的合法配对，不只留下半组消息 |
| 3. 摘要旧对话 | 概括旧目标、约束、已确认结论、进度和未解决问题 | 当前用户要求与近期必要消息保留原文；摘要不能替代文档引用 |
| 4. 裁剪兜底 | 摘要未授权、失败或额度耗尽时，舍弃较旧、低优先级内容 | 不静默删除当前要求、系统规则或当前必需的工具结果 |
| 5. 最终检查 | 重新计数并验证消息关系 | 必须保留的内容仍超限时返回 context_limit_exceeded，不发送超限请求 |

压缩必须有界：每轮重新计数，达到预算即停止，不能无限摘要或循环重试。
摘要请求本身也限制输入和输出，并经过工具授权；取消请求仍按取消处理，不能吞掉后继续执行。
工具字符上限继续作为资源保护，不能代替模型请求的 Token 预算。

## 7. 更新、保留与诊断

- 首次检索结合当前用户输入和有界的近期对话；避免仅凭“继续刚才那个方案”召回。
- 本次成功修改或删除记忆后，下一次模型调用前使相关候选失效并重新读取；任务主题变化时按需刷新。
- 未发生变化时复用本任务候选，不每次重查。建议每次任务最多额外刷新 2 次；额度耗尽时丢弃失效候选，不继续注入旧值，下一任务重新检索。刷新不扩大范围或默认重查全部 RAG。
- RAG 继续由 Agent 按需调用工具。结果纳入统一预算，跨次检索按来源、版本和块 ID 去重。
- 检索与结果找回仍经过 Application、ToolExecutor 和范围检查；失效引用应重新读取或明确报告无法找回。
- 临时选择和工具正文清理只影响本次请求，不因此删除长期记忆或清空检查点。
  正式对话摘要按官方消息状态更新，并仅在启用会话时随检查点保存；不自动转成长期记忆。
- 会话继续不默认保存原始工具输出。仅保存允许保留的来源引用、必要摘要及版本；不新建原始输出仓库。
- 每次模型请求记录各类内容用量、计数方式、实际来源及压缩原因；默认不记录正文、密钥或未脱敏工具参数。

## 8. 框架复用与自定义范围

复用 `ModelRequest` 和官方中间件扩展点进行请求调整；复用
`ContextEditingMiddleware` / `ClearToolUsesEdit` 清理旧工具输出，
`SummarizationMiddleware` 摘要对话，`trim_messages` 做裁剪。
这些能力见 [官方中间件文档](https://docs.langchain.com/oss/python/langchain/middleware/built-in)
与 [短期记忆文档](https://docs.langchain.com/oss/python/langchain/short-term-memory)。

项目只补充完整预算、来源与版本去重、业务保留规则和受控刷新。
单纯配置现有组件不能覆盖这些跨模块约束，需要小范围的协调与适配；
实际执行顺序通过最终请求测试确认，不能仅凭中间件列表顺序推断。
不重写通用压缩算法，优先使用现有依赖；新增依赖必须另行说明用途和维护成本。

## 9. 实施顺序与验收

实现依次覆盖以下范围，并已同步调用方、类型检查和文档：

1. 统一数据与组装入口，接入完整计量、输出预留和最终预算检查；覆盖持久化及非持久化运行。
2. 去除 RAG 重复正文，接入旧工具清理、摘要和裁剪，保证必要消息与调用关系。
3. 接入有界记忆刷新、来源找回和每次请求的选择记录。

验收直接捕获发给模型的完整请求，而不只测试 ContextBuilder 的中间结果：

- 大系统提示、大工具定义、多轮工具结果及临时记忆共同参与预算；输出配置与预留一致。
- 未启用会话也能压缩；当前用户要求和工具调用配对不会被破坏。
- 重复 RAG 正文只出现一次，引用仍指向原文；压缩后可重新获得必要来源。
- 摘要失败、未授权或额度耗尽时按规则降级；必要内容超限时不发送请求。
- 修改、删除、跨项目隔离和引用失效可正确处理；刷新不产生无界调用。
- 跨进程续聊保留允许保留的内容，日志和检查点不新增原始工具输出或秘密泄露。

运行 Pyright、相关 Ruff 检查、全量 unittest 和 doctor；涉及资源或入口变化时执行 uv build。
本次未新增数据库表；任务状态栏使用版本化的检查点 JSON。后续持久化结构变化仍须提供迁移并说明旧数据处理方式。
