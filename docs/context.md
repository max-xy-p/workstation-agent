# 上下文管理与任务状态栏

每次模型调用前，Context 检查完整请求、选择相关信息并限制输入体积。
任务状态栏保存目标和进度，帮助模型在旧消息被压缩后继续任务；它是结构化数据，当前没有对应前端。

## 配置与运行

兼容服务使用自定义模型时，配置真实容量，不要直接照用示例数值：

```powershell
$env:WORKSTATION_AGENT_CONTEXT_WINDOW = '32768'
uv run workstation-agent doctor --agent
uv run workstation-agent run "检查项目结构" --transport local `
  --constraint "只读取文件" --criterion "列出模块职责"
```

`doctor --agent` 不发送模型探测请求，仍按默认 MCP 入口检查工具服务令牌。
返回的 `task_status` 是最终状态栏，步骤中的 `context_usage` 记录每次请求用量；
应用可通过 `on_status` 回调取得节点完成后的状态。

## 请求预算

以下名称统一加 `WORKSTATION_AGENT_CONTEXT_` 前缀：

| 名称 | 默认值 | 用途 |
| --- | --- | --- |
| WINDOW | 空 | 模型上下文窗口；缺省时使用框架公开模型资料，没有资料则拒绝运行 |
| INPUT_LIMIT | 空 | 单独输入上限，未设置时使用窗口或模型资料 |
| OUTPUT_LIMIT | 空 | 模型输出能力上限，未设置时读取模型资料 |
| OUTPUT_TOKENS | 2048 | 给输出预留的 Token，同时设置实际模型请求的 `max_tokens` |
| SAFETY_TOKENS | 1024 | 输入与输出之外的安全余量 |
| TRIGGER_RATIO | 0.8 | 输入预算达到此比例时开始清理或摘要 |
| SUMMARIZE | false | 是否尝试额外摘要；还需 `MEMORY_ALLOW_REMOTE=true` 授权出站 |
| REFRESH_LIMIT | 2 | 单次任务首次召回之外允许的记忆刷新次数 |
| BOARD_TOKENS | 1024 | 状态栏可选内容的输入上限，实际最多使用输入预算的四分之一 |

可用输入为 `min(输入上限, 窗口 - 输出预留) - 安全余量`。
计量包括系统规则、历史、当前要求、工具定义/参数/结果、结构化输出约束、状态栏、记忆和 RAG。
显式配置优先，缺省才读取模型资料；容量未知时拒绝运行，不猜测自定义模型窗口。

输出预留同时设置实际请求的 `max_tokens`，不能超过模型输出上限。
不能精确计数时采用官方近似计数与 UTF-8 字节保护，`counter` 标明方式；服务返回 usage 时另记实际用量。
这些数值不是精确计费量，当前仅支持文本预算，不适用于图像和音频。

必要内容仍超限时，不发送请求，返回 `limit_reached` 与 `context_limit_exceeded`。
普通 `doctor` 允许不配置模型容量，运行任务时必须有可用预算。

## 任务状态栏

| 字段 | 内容 |
| --- | --- |
| goal / current_request | 初始目标与本轮要求，仅用户入口可修改 |
| criteria / constraints | 用户显式验收条件与限制 |
| items | 待办、进行中、待确认、已完成或阻塞的任务项 |
| facts / results | 简短事实及来源，成功工具调用与允许保留的位置、版本 |
| blockers / next_action | 阻塞原因与下一步 |
| task_id / session_id / revision | 任务和会话身份，以及用户验收的状态版本 |

`--session chat` 保存状态并续聊；`--constraint`、`--criterion` 在续聊时追加条件，
`--new-task` 新建状态栏但保留消息。自然语言不会被规则程序自动拆成验收条件。

模型通过受控的 `update_task_status` 工具更新进度，每轮仅允许一次，不能改用户目标、授权文件写入或写长期记忆。
模型报告完成须提供成功结果引用，但“工具成功”不等于“任务验收通过”；项目先进入 `pending_confirmation`。
用户核对后明确确认，以下占位值替换为返回状态中的实际内容：

```powershell
uv run workstation-agent confirm-status chat --transport local --task-id task-id --revision 7 --item test
```

旧任务、旧版本或非待确认项目不能验收。事实“已确认”只代表文字可在来源中核对，不证明现实真实性。
模型返回最终答复也不会自动把全部任务项改成完成。
仅更新下一步时保留其他内容，显式提交空列表才清空对应字段。

完整状态与模型输入分开：每次保留目标、限制和验收条件，再按预算选择阻塞、下一步、未完成项和近期事实，
已完成项优先级最低。按完整条目选择，省略项仍保存在状态中；必要内容过大时停止，不静默截断。

## 压缩与刷新

每次请求按以下顺序处理：

1. 使已修改/过期记忆及其引用失效，在额度内刷新候选。
2. 按来源、版本和块 ID 去重，RAG 原文只发送一份。
3. 超过触发阈值时清理旧工具正文，保留最近完整结果。
4. 启用摘要且获得 `MEMORY_ALLOW_REMOTE` 授权时摘要旧对话，保留当前用户原文。
5. 仍不足时按整条舍弃检索候选，再裁剪旧历史。
6. 重算最终请求并检查工具调用/结果配对，通过后才发送。

摘要每次运行最多尝试一次；失败、未授权或额度耗尽时裁剪兜底，取消继续传播。
首次记忆查询结合当前要求与有界近期对话，本任务内可复用；成功记忆变更或 RAG 主题变化后按需刷新。
额度耗尽则丢弃失效内容，不继续注入旧值；不扩大范围或默认重查全部知识库。
外部进程的记忆变更在下次任务检索时反映。

临时清理和裁剪只影响请求，不删除保存的文本；正式摘要通过官方消息更新保存。
会话持久化时状态栏随官方检查点保存，格式迁移与框架升级约束见 [开发指南](development.md#运行与上下文维护)。

## 来源找回与保留

RAG 引用包含位置与 checksum，重取时核对版本。
文件工具可用 `offset`、`limit`、`expected_version` 继续读取，变化时返回 `source_changed`，
所有请求仍限制在工作区内；输出上限太小时分页提示也可能截断。

未启用会话时，状态仅存在于本次运行；检查点不保存工具正文和 artifact，状态保留必要简短事实。
用量步骤仅记录数量、计数方式、来源 ID 与舍弃原因，不复制原始消息。
删除记忆不会清除模型曾复述的历史；需要时另外 [清除会话](agent.md#会话续聊)。
完整请求预算、来源刷新及用户验收为何需要少量自定义适配，见 [架构](architecture.md#框架选择与必要扩展)。
