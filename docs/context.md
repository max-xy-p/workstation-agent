# 上下文管理与任务状态栏

上下文模块在每次模型调用前检查完整请求，决定哪些历史、工具结果和检索内容可以发送。
任务状态栏保存当前工作的目标与进度，帮助模型在旧对话被压缩后继续处理任务。
它是 AgentState 中的一份结构化数据；本次没有新增桌面界面。

## 配置和运行

运行任务前需要配置模型、API Key，以及模型的真实容量。兼容服务使用自定义模型时，
必须显式配置窗口；不要把示例数值当成实际服务的容量。

```powershell
# 以下 32768 仅为示例，请替换成部署模型的真实上下文窗口。
$env:WORKSTATION_AGENT_CONTEXT_WINDOW = '32768'
uv run workstation-agent doctor --agent
uv run workstation-agent run "检查项目结构" --transport local `
  --constraint "只读取文件" --criterion "列出模块职责"
```

`doctor --agent` 只检查本地配置，不发送模型探测请求；该诊断仍按默认 MCP 入口检查服务令牌。
任务返回 JSON 中的 `task_status` 是最终状态栏，`steps` 中的 `context_usage` 是每次请求的用量记录。
开发者也可以给 `AgentApplication.run_task` 传入 `on_status` 回调，在图节点完成时接收状态。

`--session chat` 启用检查点并续聊，状态栏随会话恢复。继续同一会话时，
`--constraint` 和 `--criterion` 追加用户指定的条件；`--new-task` 开始新的状态栏，仍保留会话消息。
用户输入的自然语言不会被规则程序自动拆成验收条件；需要稳定保留的条件通过这些参数明确提供。

## 请求预算

以下环境变量均带 `WORKSTATION_AGENT_CONTEXT_` 前缀：

| 名称 | 默认值 | 用途 |
| --- | --- | --- |
| WINDOW | 空 | 模型上下文窗口；缺省时使用框架公开模型资料，没有资料则拒绝运行 |
| INPUT_LIMIT | 空 | 单独输入上限，未设置时使用窗口或模型资料 |
| OUTPUT_LIMIT | 空 | 模型输出能力上限，未设置时读取模型资料 |
| OUTPUT_TOKENS | 2048 | 给输出预留的 Token，同时设置实际模型请求的 `max_tokens` |
| SAFETY_TOKENS | 1024 | 输入与输出之外的安全余量 |
| TRIGGER_RATIO | 0.8 | 输入预算达到此比例时开始清理或摘要 |
| SUMMARIZE | false | 是否尝试额外摘要；还需 `MEMORY_ALLOW_REMOTE=true` 授权出站 |
| REFRESH_LIMIT | 2 | 单次任务首次召回之外允许的记忆刷新次数 |
| BOARD_TOKENS | 1024 | 状态栏可选内容的输入上限，实际最多使用输入预算的四分之一 |

可用输入为 `min(输入上限, 窗口 - 输出预留) - 安全余量`。
计量包括系统规则、历史、当前要求、工具参数与结果、任务状态栏、记忆、RAG，
以及工具定义和结构化输出约束。显式配置优先于框架资料，输出预留不得超过最终采用的输出上限。
模型计数接口不能使用时，复用官方近似计数，并以 UTF-8 文本和工具参数字节数作保守保护。
工具定义按序列化字节数估算。`counter` 会说明计数方式；这些数值不是服务端精确计费量。
服务返回 usage 时，额外记录实际输入、输出 Token，便于比较误差。

普通 `doctor` 允许不配置模型容量；`doctor --agent` 和真正运行任务时必须有可用预算。
窗口太小或必要内容超限时，不发送请求，任务返回 `limit_reached` 和 `context_limit_exceeded`。
当前计量只接受文本内容；不能使用文本预算估算图像、音频请求。

## 状态栏保存什么

| 字段 | 内容和更新权限 |
| --- | --- |
| goal / current_request | 初始用户目标与本轮要求；用户入口更新，模型工具不能修改 |
| criteria / constraints | 用户显式提供的验收条件与约束；续聊时追加 |
| items | 任务项及 pending、in_progress、pending_confirmation、completed、blocked 状态 |
| facts | 简短事实或判断，以及来源 ID、是否已确认 |
| results | 成功工具调用的 ID、工具名和允许保留的位置、版本字段 |
| blockers / next_action | 当前阻塞和下一步；工具失败也会写入安全的阻塞说明 |
| task_id / session_id / updated_at / revision | 任务身份、会话身份、UTC 更新时间和用户验收使用的状态版本 |

模型通过 `update_task_status` 工具更新进度字段，同一轮只允许调用一次，避免并行覆盖。该工具声明参数 schema 和写权限，
经过 ToolExecutor，只允许修改当前运行内的状态，不获得任何文件写入或长期记忆写入权限。
模型报告完成时必须提供成功结果引用，但工具成功本身不能证明某个任务项通过验收。
例如列目录成功，并不能证明“测试通过”。系统将完成报告保存为 `pending_confirmation`，
只有用户入口核对任务 ID、状态版本和任务项 ID 后才能改为 `completed`：

```powershell
# chat 是保存的会话；task-id、7 和 test 都需替换为 task_status 中实际的值。
uv run workstation-agent confirm-status chat --transport local --task-id task-id --revision 7 --item test
```

旧任务、旧状态版本或非待确认项目不能验收；模型工具没有这个权限。
对话中一句“已完成”也不会自动变成其他项目的验收凭据。
确认事实仍要求逐字出现在可读来源中，表示来源包含这段文字，不表示程序证明了现实中的真实性。
只提交 `next_action` 会保留已有任务项、事实和阻塞；显式提交空列表才清空相应字段。
模型结束回答只代表本次 Run 已返回答复，不会自动把所有任务项标记为完成。

完整状态和模型输入分开保存。每次请求保留目标、约束和验收条件，
再按预算选择阻塞、下一步、未完成项目和近期事实；已完成项目优先级最低。
不重复发送当前用户原文，也不发送全部来源位置、时间和身份字段。
选择按完整条目进行，省略的内容仍保留在状态栏中；用量原因记录 `projected_task_board`。
必要的目标与限制超过预算时仍停止，不会为满足状态栏上限而静默截断。

状态栏有条目数量和文本长度限制。目标、约束和当前要求不会为腾出预算而静默截断；
它们本身过大时明确停止。工具正文不复制到 results，所需原文继续通过授权工具读取。
状态栏不自动写入长期记忆。

## 压缩与刷新

每次模型调用按顺序执行：

1. 检查成功的记忆变更和主题信号，失效旧候选及状态栏中依赖这些记忆的事实和引用，在额度内通过受控记忆入口重新查询。
2. 按来源、版本、块 ID 去重；RAG 模型输入只保留一次证据正文，完整结果仍在工具 artifact 中。
3. 超过触发阈值时，使用官方 `ClearToolUsesEdit` 清理较旧工具正文，最近一组完整结果保留。
4. 启用且获得授权时，使用官方 `SummarizationMiddleware` 摘要旧对话；当前用户要求不参加摘要。
5. 预算仍不足时，按完整条目舍弃检索候选，并使用官方 `trim_messages` 裁剪旧历史。
6. 重新计量最终请求并检查工具调用与结果是否完整配对，成功后才调用模型。

摘要与最终请求检查在不同官方扩展点协调：`before_model` 可以正式更新摘要消息，
`wrap_model_call` 位于消息、工具和临时数据组装之后，负责发送前的最后检查。
可选摘要每次运行最多尝试一次，实际摘要模型请求也限制输入和输出。
官方摘要组件的失败重试可能增加等待时间，但授权包装器禁止第二次出站调用。
摘要失败、未授权或额度耗尽时使用裁剪，取消信号继续向上传递。

首次记忆查询包含有界近期对话和当前要求。同一运行候选可复用；
成功新增、更新、删除记忆或成功 RAG 查询指示主题变化后按需刷新。
刷新额度耗尽时丢弃失效候选，不继续注入旧值；过期候选也会排除。
刷新不扩大用户、工作区或项目范围，也不自动重查整个知识库。
当前不订阅其他进程的记忆变更，外部变更在下次任务首次检索时反映。

临时工具清理、去重和裁剪不修改原消息历史；正式摘要通过官方消息更新保存。
删除记忆不能清除模型先前已经复述到对话中的内容，清除这类历史需另行清理会话。

## 找回被压缩的来源

RAG 引用保留文档位置和 checksum；重新检索时核对版本，不把旧版本引用当作当前原文。
文件工具 `read_text_file` 支持字符参数 `offset`、`limit`、`expected_version`。
超长结果返回 `next_offset` 和文件版本，继续读取时带上该版本；文件变化则返回 `source_changed`。
所有分段请求仍限制在工作区内，单次读取与最终工具输出均有长度限制。
只配置极小的工具输出上限时，分页提示也可能被输出保护截断，应提高该上限或明确指定小范围。

## 保存和旧数据

未启用会话时，状态栏仅存在于本次运行，CLI 返回后不会自动写盘。
异常停止时，回调提供停止原因；检查点保留最后成功节点的状态，审批恢复、超时和取消见 [运行控制](run-control.md)。
启用会话时，状态栏是官方检查点的 JSON channel，不创建新的业务表，SQLite 表仍由官方维护。
`schema_version=2` 标识状态栏格式；`restore_board` 是其版本迁移入口：
旧检查点缺少状态栏时初始化新状态；格式 1 会升级为格式 2，旧的完成项目改为待确认，
避免把旧版仅校验成功引用的结果当成用户验收。未知版本拒绝加载。
使用 `--new-task` 可明确放弃旧状态栏并建立新状态；后续增加版本须在此入口添加显式迁移。
这次没有修改 SQLite 表结构，因此不新增 SQL migration，也不需要重建记忆或 RAG 索引。

检查点继续清除工具正文和 artifact，并脱敏已知秘密；状态栏保留用户目标和必要的简短事实。
用量步骤只记录数量、计数方式、来源标识及舍弃原因，不复制原始消息或工具参数。
状态回调接收的内容属于任务数据，调用方应按会话访问权限处理。

## 自定义范围与验收

复用现有 LangChain/LangGraph：官方 Agent 循环、ModelRequest、ToolRuntime、Command、
ClearToolUsesEdit、SummarizationMiddleware 和 trim_messages，没有新增运行依赖。
通用 TodoListMiddleware 允许自由标记完成，不能满足用户目标不可改和完成凭据要求，
因此仅自定义状态字段校验与状态工具；不引入规划引擎。
框架没有提供本项目所需的完整请求预算、来源版本去重和受控刷新协调，因此保留小型适配。
框架扩展要求的 `dict[str, Any]` 仅用于中间件返回值和官方合并状态的组装边界；
工具 JSON 参数立即经过 ToolExecutor 转成明确模型，业务依赖通过 Protocol 声明。
当前按锁定版本 LangChain 1.4.3、LangGraph 1.2.12 验收；公开模型资料 profile 仍是 Beta 接口，
只读取有默认值保护的容量字段。结构化输出复用官方策略的 schema_specs 与 OutputToolBinding，
逐个计入可能的输出工具，并有 Union 格式回归。维护成本集中在官方请求绑定与摘要接口；升级框架时需重新运行最终请求捕获和检查点测试。

运行仓库 Pyright、相关 Ruff、全量 unittest、doctor 和 uv build。
新回归直接捕获模型实际收到的消息和最大输出参数；离线验收不代表已验证外部模型的摘要质量。
